# SPLICE LOCAL OPERATOR — Windows + Chrome + OKX

这是 FAST-2C 本地部署工具。开发阶段没有部署、没有真人签名、没有链上写入。原授权剩余 **4/4**。本包的自动化测试是 MOCK，不是链上成功证据。

## 只需要这样做

1. 下载完整 ZIP，右键 → 全部解压。不要在 ZIP 预览里运行。
2. 双击 `START_SPLICE_LOCAL.cmd`，保留黑色窗口打开。
3. Chrome 自动打开 `http://127.0.0.1:4179`。未自动打开时，在已有 OKX 扩展的 Chrome 配置中打开这个地址。
4. 选择 OKX Provider，勾选确认，点 **CONNECT OKX WALLET**。必要时点 **配置 / 切换 61999 网络**，由你确认钱包授权。
5. 当前账户应为 A。环境显示 **READINESS PASS** 后，点 **准备 T01（只读）**，检查参数，勾选费用说明，再点 **SIGN T01 IN OKX**。核对钱包弹窗后亲自签名。
6. 等 T01 显示 VERIFIED，按同样方式执行 T02。
7. 页面提示 **SWITCH TO WALLET B** 时：打开 OKX 扩展 → 点击顶部账户名 → 选择已有账户 B。页面自动读取地址，B 必须与 A 不同。点一次 **本地只读环境检查**，再独立准备、签名 T03。
8. 页面提示切回 A：在 OKX 中选回 T01 记录的原始 A 地址，点一次 **本地只读环境检查**，再独立准备、签名 T04。
9. T04 返回真实作品后，核对双方源特征与融合描述，勾选三项语义核对，再点确认。需要记录更详细证据时，可展开可选原文片段。此操作不发交易。
10. 点 **EXPORT EVIDENCE**。浏览器下载 JSON。把这个文件带回聊天供下一阶段核验；工具不会自动上传。

四笔交易都需要你分别点击，互不自动连续发送。预检结果有效 60 秒；及时核对并点击签名。只读操作无需签名。

## 第一次启动缺少 Node.js

只需安装一次。打开官方 https://nodejs.org/ ，下载当前 LTS 的 Windows Installer，保留默认安装选项和 PATH 设置。要求 Node.js 22.12 或以上。安装后重新双击启动文件。无需 Python、私钥文件或编辑源码。

依赖不存在时，启动脚本用本包 `package-lock.json` 执行 `npm ci --ignore-scripts`。首次需要连接 npm 官方包源；如果无法下载，脚本会停止，保留原始错误。不会自动切换第三方包源或下载未知程序。依赖已安装且预构建存在时直接启动。

本包包含构建好的静态界面和完整源码。启动脚本只运行本地已提供的脚本。可右键 `.cmd` → 编辑查看内容。`VERIFY_SOURCE.cmd` 可独立复核源码及交付文件 SHA256。

## 钱包签名前必须核对

- 钱包确实是 OKX，账户与页面显示的 A/B 一致。
- 网络仅为 Stable GenLayer Studionet，61999 / `0xf22f`。
- RPC 仅为 `https://studio.genlayer.com/api`。
- 交易转账金额 value 为 0；预计网络费用为 0；Gas Price 为 0。
- T01 的外层 to 是 SDK 固定的共识入口，内部部署 recipient 为零地址。这不是假 SPLICE 地址；部署成功后才取得真实合约地址。
- T02/T03/T04 的外层仍为共识入口；内部目标为已经验证的 SPLICE 合约地址。
- 不输入、发送或导入任何助记词、私钥、钱包密码或验证码到本工具。

若钱包弹窗显示任何非零费用或转账金额，**拒签并停止**。拒签后不允许在此流程重试。失败、未知广播、RPC 错误或非零费用均停止后续写入，禁止第 5 笔。

## 本机 RPC 检查

连接后自动检查；切换账户后点 **本地只读环境检查**。检查双路径的真实 chain ID、余额、Gas Price；准备每笔交易时再执行完整参数估费。SDK 只读请求也需成功才能生成可签名参数。

- **NETWORK BLOCKED**：HTTP 403 会明确显示；浏览器级 CORS、网络、超时不能总是可靠区分，会保留可能原因。
- **WALLET BLOCKED**：账户、钱包或链不符。不要切换签名工具绕过。
- **SIGNING BLOCKED**：签名参数异常、拒签、未知广播或状态。
- **RPC UNSUPPORTED**：方法或响应结构不兼容。
- **READINESS PASS**：本次只读检查通过；不是链上部署成功。

Work 云端的 403 不代表本机必然失败。工具不切换测试网络，不使用备用第三方 RPC，也不调用旧费用接口。

EIP-1193 无法反查钱包内部保存的 RPC URL。工具使用固定参数请求添加 / 切换网络，再分别验证钱包和官方 RPC 的链 ID、费率、余额和估费。请在 OKX 网络设置确认 RPC URL 与上方一致。

## 刷新、超时、异常恢复

固定用 `http://127.0.0.1:4179`，同一 Chrome 配置中仅保留一个操作页。已保存的 intent、Hash、地址、请求 ID 和阶段在刷新后恢复。页面不会自动重发。

有 Hash：点击该阶段的 **只读重新查询**。查询不会发新交易。暂时的只读障碍排除并完整验证该笔成功后可恢复后续阶段；明确的共识失败、拒签或非零费用保持停止。

钱包显示已发送但页面没有 Hash：从 OKX 交易历史复制真实 Hash，在 **钱包已有 Hash，但页面未收到 / 未保存** 中补录。只有已有、尚无 Hash 的 intent 可以补录，之后必须核对账户、nonce、calldata、真实源码 / 合约和结果。不得换 request_id 重发。

没有保存 intent 或浏览器存储已被清理：停止，保留钱包历史并交回人工调查。不要从 T01 重新运行。不要清理站点数据、切换端口、切换 Chrome 配置、手改存储或打开另一份包来“解决”阻断。任何本地软件都无法在用户清空全部状态或手工绕过后保证原交易额度；本工具不提供清空或重置按钮。

端口 4179 已占用时启动脚本停止；先关闭已有操作台窗口，不换端口继续。关闭页面不会撤销已经提交的链上交易。

## 证据范围

JSON 含公开 A/B 地址、真实 Hash、原始共识 / 执行响应、作品 ID、get_work/get_lineage、重算哈希、Gas 回执与费用、未验证事项。未运行阶段明确写 NOT RUN。语义确认保存你的三项人工比较结果，以及可选的真实原文片段；不以关键词匹配声称独立 AI 语义验证。

本包不包含私人钱包记录、实际交易证据或模拟成功报告。测试结果与界面中的 MOCK 标识不代表真人 E2E。只有完成全部真实交易、读取、谱系及人工语义核对后才能显示 REAL ONCHAIN FUSION VERIFIED。
